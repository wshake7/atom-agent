## Question

规格里的**实现迭代路线图**分成哪些阶段，每阶段的退出条件（阶段边界）是什么？

前序票锁死内核、插件契约、v0 边界、企业接缝之后，把它们编成可交接的阶段序列。至少裁定：

- 阶段名称与顺序（从能跑的 coding CLI 内核，到插件面稳定，再到企业接缝可用）。
- 每阶段：必须有的、明确没有的、不得破坏的不变量。
- 何谓「阶段完成」：可检验的退出条件，不是愿望清单。
- 哪一阶段之后才允许谈可嵌入 Runtime / 多智能体平台的实现（本图仍不实现它们）。

本票的答案应能直接粘进规格的路线图章节。不写代码，不把阶段拆成工程任务列表。

## Answer

到 v0 共六段，其后加槽本图不排序。ADR：[到 v0 产品闭环共六段，其后加槽不排序](../../../docs/adr/0005-roadmap-six-phases-to-v0.md)。

全程不变量：官方槽 `loop`/`tools`/`llm` 语义不改；内核无第五件套；无 TUI、无权限弹窗、无浏览器/多智能体/IDE。后续阶段至多加槽。

| 阶段 | 必须有 | 明确没有 | 退出条件 |
| --- | --- | --- | --- |
| 宿主 | 四件套：注册、注入、生命周期、匿名事件 | 业务事件名、发现逻辑、`loop` 语义 | 能加载/卸载同进程插件并发匿名事件；无循环也算过 |
| 默认循环插件 | 占 `loop`，能完成模型 ↔ 工具回合 | CLI、真模型、真实仓库工具 | 假 `llm`/假工具下跑完一轮 |
| `llm` 端口 | 真模型接到 `llm` 槽 | 多提供商市场 | 一次真实模型调用成功 |
| 流式 REPL | 终端流式一轮 | 差分 TUI | 人能在 REPL 打完一轮并看见流式输出 |
| 默认工具包 | `read`/`write`/`edit`/`bash`/`grep`/`glob`/ASK 一整包，均可关 | 每工具单独成阶段；权限拦截 | 能读改当前仓库、跑命令、搜索、问答 |
| MCP 工具桥 | 把某 MCP server 的 tools 登记进 `tools` | resources/prompts/sampling | 登记后的工具能被循环调用。**此阶段退出 = v0 产品闭环** |

v0 产品闭环之后才允许谈可嵌入 Runtime / 多智能体的实现（本图仍不实现）。会话持久、可观测、权限/沙箱等后续阶段本图不排序。

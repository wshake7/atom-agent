## Question

插件契约要覆盖哪些**可替换面**，以及加载、隔离、版本的硬约束是什么？

在「内核最小闭合集」已锁的前提下，裁定：

- 可替换面：模型、工具、钩子、记忆、提示词、UI、协议……哪些是 v0 契约，哪些只留接缝。
- 内置 coding 工具如何仍算插件（内置分发 ≠ 核内实现）。
- 发现与加载：本图要锁到什么粒度（进程内接口即可，还是必须说清目录/包规范）。
- 隔离与版本：v0 是否进程内；契约版本破坏时怎么办。

不设计插件市场，不排企业阶段。

## Answer

插件同构：注册 / 注入 / 生命周期，向 Context 贡献服务。v0 官方槽只有 `loop`、`tools`、`llm`；未点名键仍可贡献。官方槽语义不可改，新能力只加新槽。ADR：[插件同构，v0 只点名三个槽](../../../docs/adr/0002-plugin-slots.md)。

加载：契约只锁进程内加载面（已解析模块 + 依赖）；发现、目录、npm 不进本契约。隔离是能力级——模块同进程加载；沙箱/子进程若出现，是某槽提供方，且不是 v0 官方槽。内置 coding 工具是默认装上的 `tools` 槽插件，与第三方同一加载面，可关可换；同包分发 ≠ 进内核。具体哪几把工具见 [v0 Coding CLI 产品边界](./06-v0-coding-cli-product-boundary.md)。
